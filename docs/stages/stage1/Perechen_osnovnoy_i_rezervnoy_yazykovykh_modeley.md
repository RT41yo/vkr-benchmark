# Перечень основной и резервной языковых моделей

## 1. Назначение документа

Настоящий документ фиксирует выбор основной и резервной языковых моделей для дальнейшей реализации и экспериментальной проверки общего стенда генеративной лингвистической стеганографии в рамках ВКР.

Выбор выполнен по результатам одинаковых предварительных испытаний моделей-кандидатов на NVIDIA GeForce RTX 5070 Ti 16GB VRAM.

Приоритет критериев при выборе:

1. надежность токенизации и возможность корректного восстановления последовательности токенов;
2. воспроизводимость распределения токенов;
3. запас видеопамяти;
4. скорость генерации;
5. удобство интеграции в общий экспериментальный стенд.

## 2. Основная языковая модель

### Llama-3.2-3B

**Статус:** основная языковая модель.

**Ревизия модели:**

`13afe5124825b4f3751f836b40dafda64c1ed062`

**Режим использования:**

- BF16;
- batch size 1;
- без квантования;
- `eval()`;
- без вычисления градиентов;
- пошаговая генерация с KV-кэшем.

### Основания выбора

Llama-3.2-3B успешно прошла все обязательные технические проверки:

- размещается в 16GB VRAM;
- работает при контексте 2048 токенов с генерацией 256 новых токенов;
- предоставляет полный вектор логитов;
- поддерживает ручную генерацию с KV-кэшем;
- повторные вычисления в одинаковом режиме дают идентичные логиты и top-100;
- все 30 реально сгенерированных последовательностей успешно проходят `tokens → text → tokens`;
- размер выходного пространства модели полностью совпадает с размером токенизатора;
- отсутствуют выходные ID модели, не имеющие отображения в токенизаторе.

### Основные измеренные характеристики

- VRAM после загрузки: около 5.985 ГБ;
- максимальный пик VRAM при 2048 + 256 токенах: около 6.354 ГБ;
- скорость decode:
  - 128 токенов контекста: около 94.82 токен/с;
  - 512 токенов контекста: около 90.45 токен/с;
  - 2048 токенов контекста: около 77.12 токен/с;
- стабильность отдельных токенов `id → text → id`: 98.95 %;
- реальный sequence round-trip: 30/30;
- повторный top-100 в одинаковом режиме: 100 %;
- минимальное пересечение top-100 при сравнении KV-cache и полного пересчета: 97 %.

### Причина выбора основной моделью

Llama-3.2-3B требует меньше видеопамяти, быстрее выполняет последовательную генерацию и имеет более простое соответствие «выходное пространство модели ↔ токенизатор», чем Qwen3-4B-Base.

Это уменьшает число специальных случаев в общей инфраструктуре и оставляет больший запас ресурсов для реализации стеганографических методов и дополнительных измерений.

## 3. Резервная языковая модель

### Qwen3-4B-Base

**Статус:** резервная языковая модель.

**Ревизия модели:**

`906bfd4b4dc7f14ee4320094d8b41684abff8539`

**Режим использования:**

- BF16;
- batch size 1;
- без квантования;
- `eval()`;
- без вычисления градиентов;
- пошаговая генерация с KV-кэшем.

### Основания сохранения в качестве резервной

Qwen3-4B-Base также успешно прошла обязательные технические проверки:

- размещается в 16GB VRAM;
- работает при контексте 2048 токенов с генерацией 256 новых токенов;
- предоставляет полный вектор логитов;
- поддерживает KV-кэш;
- повторные вычисления в одинаковом режиме полностью воспроизводимы;
- все 30 реально сгенерированных последовательностей успешно проходят `tokens → text → tokens`.

### Основные измеренные характеристики

- VRAM после загрузки: около 7.545 ГБ;
- максимальный пик VRAM при 2048 + 256 токенах: около 7.987 ГБ;
- скорость decode:
  - 128 токенов контекста: около 70.35 токен/с;
  - 512 токенов контекста: около 66.59 токен/с;
  - 2048 токенов контекста: около 55.47 токен/с;
- стабильность отдельных токенов `id → text → id`: 97.79 %;
- реальный sequence round-trip: 30/30;
- повторный top-100 в одинаковом режиме: 100 %;
- минимальное пересечение top-100 при сравнении KV-cache и полного пересчета: 96 %.

### Особенность интеграции

У Qwen3-4B-Base размер выходного пространства модели равен 151936, тогда как токенизатор содержит 151669 ID.

Имеются 267 выходных ID модели, не имеющих отображения в токенизаторе.

В общем стенде эти ID должны исключаться из допустимого множества токенов до передачи распределения стеганографическому методу, после чего вероятности должны быть перенормированы.

Также необходимо явно исключать служебные токены согласно данным токенизатора.

### Причина выбора резервной моделью

Qwen3-4B-Base технически пригодна для полного стенда, но:

- требует больше видеопамяти;
- медленнее в последовательной генерации;
- требует дополнительной обработки 267 недоступных токенизатору выходных ID;
- имеет немного менее удобные характеристики для унифицированной реализации.

При этом модель остается важной резервной точкой, поскольку позволяет проверить переносимость общей архитектуры стенда на другую современную базовую LM.

## 4. Общие условия использования обеих моделей

Для сохранения воспроизводимости дальнейшие эксперименты должны выполняться при одинаковых базовых условиях:

- Python 3.12.14;
- PyTorch 2.7.1+cu128;
- Transformers 4.52.4;
- CUDA runtime PyTorch 12.8;
- BF16;
- batch size 1;
- без квантования;
- `eval()`;
- без градиентов;
- фиксированные ревизии моделей;
- единый алгоритм формирования допустимого множества токенов;
- единая политика special tokens;
- единый вычислительный путь с KV-кэшем;
- единая последовательность обработки распределения до передачи его стеганографическому методу.

Кодер и декодер не должны использовать разные вычислительные пути формирования распределения, поскольку вычисление с KV-кэшем и полный пересчет всего префикса в BF16 дают небольшие, но измеримые различия логитов и рангов токенов.
