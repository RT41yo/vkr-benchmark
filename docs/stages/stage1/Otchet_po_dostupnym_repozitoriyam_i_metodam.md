# Отчет по доступным репозиториям и методам генеративной лингвистической стеганографии

## 1. Цель и границы анализа

На первом этапе работы были изучены открытые репозитории методов генеративной лингвистической стеганографии и проведено их сопоставление с исходными публикациями. Основная цель состояла в том, чтобы определить, какие методы можно воспроизвести и адаптировать для единого экспериментального стенда.

Для каждого репозитория проверялись:

- связь с исходной публикацией;
- наличие кода встраивания и извлечения секретного сообщения;
- используемая языковая модель и токенизатор;
- зависимости от конкретной модели и версий библиотек;
- наличие управляемых параметров метода;
- реализованные метрики;
- возможность проверить полный цикл «секретное сообщение → стеготекст → восстановленное сообщение»;
- ограничения и ошибки реализации;
- ожидаемая трудоемкость переноса в общую инфраструктуру.

По результатам анализа для основной экспериментальной части выбраны семь методов:

**Bins, код Хаффмана, арифметическое кодирование, ADG, Discop, RRC и DAIRstega.**

Этот набор не является полным перечнем существующих методов. Его задача — представить несколько разных принципов встраивания и сформировать достаточно разнообразную основу для контролируемого многокритериального сравнения.

---

## 2. Основные изученные репозитории

Для выбранных методов основными программными источниками являются следующие репозитории:

| Репозиторий | Методы | Роль |
|---|---|---|
| `harvardnlp/NeuralSteganography` | Bins, код Хаффмана, арифметическое кодирование | основной источник трех исторических методов |
| `Mhzzzzz/ADG-steganography` | ADG | авторская реализация |
| `comydream/Discop` | Discop | авторская реализация |
| `ryehr/RRC_steganography` | RRC | авторская реализация |
| `WangYH-BUPT/DAIRstega` | DAIRstega | авторская реализация |

Общий результат анализа состоит в том, что ни один из рассмотренных репозиториев нельзя без изменений использовать как готовый модуль общего экспериментального стенда.

Основные причины:

- часть реализаций создана для устаревших версий библиотек;
- некоторые методы жестко привязаны к GPT-2, LLaMA 2 или собственной рекуррентной модели;
- не во всех репозиториях есть декодер;
- одинаково называемые метрики часто рассчитываются по-разному;
- в отдельных реализациях теоретическое значение KL-дивергенции записывается как ноль без независимого измерения;
- встречаются ошибки, связанные с токенизацией, вычислительной точностью, остановкой генерации и подсчетом статистик;
- не всегда зафиксированы версии моделей, токенизаторов и библиотек.

Поэтому открытые реализации целесообразно использовать как первичный программный источник алгоритма, а само математическое ядро каждого метода переносить в общую инфраструктуру.

Предлагаемая схема работы:

\[
\text{исходная публикация}
\rightarrow
\text{открытая реализация}
\rightarrow
\text{адаптированная реализация}
\rightarrow
\text{проверка соответствия}.
\]

При этом для всех методов должны использоваться одинаковые внешние условия: языковая модель, токенизатор, входные данные, секретные битовые последовательности, эталонное распределение обычной генерации и единый набор метрик.

# 3. Bins

## 3.1. Исходная работа и реализация

Метод Bins связан с работой Fang, Jaggi и Argyraki *Generating Steganographic Text with LSTMs* (2017).

Для практического анализа использовалась более поздняя реализация из репозитория:

`https://github.com/harvardnlp/NeuralSteganography`

В этом репозитории Bins реализован как один из базовых методов для сравнения с арифметическим кодированием.

## 3.2. Принцип работы

Словарь языковой модели заранее делится на несколько непересекающихся групп — корзин.

Если используется \(2^b\) корзин, каждая корзина соответствует последовательности из \(b\) секретных бит. Например, при \(b=2\) используются четыре группы, соответствующие комбинациям:

\[
00,\ 01,\ 10,\ 11.
\]

На каждом шаге кодер читает очередные \(b\) бит, выбирает соответствующую корзину и затем выбирает из нее наиболее вероятный токен по распределению языковой модели.

Декодер по принятому токену определяет его корзину и восстанавливает биты.

## 3.3. Значение для исследования

Bins важен как простой исторический базовый метод.

Он позволяет заранее определить число передаваемых бит на токен и почти не требует сложных вычислений. Одновременно метод хорошо демонстрирует основной недостаток фиксированного разбиения: секретные биты могут заставить кодер выбирать токены из маловероятной корзины, что создает заметное статистическое искажение.

Таким образом, Bins дает полезную нижнюю точку отсчета по оси «емкость — искажение распределения».

## 3.4. Ограничения реализации

Код в `NeuralSteganography` исторически привязан к GPT-2 и использует внутренние особенности старого токенизатора и интерфейса модели.

Поэтому переносить исходный файл без изменений не следует. При этом сам алгоритм прост и легко отделяется от конкретной языковой модели.

## 3.5. Решение

**Bins включается в основной набор.**

Основной параметр метода:

\[
b
\]

— число секретных бит, которое задает количество корзин.

# 4. Код Хаффмана

## 4.1. Исходная работа и реализация

Метод связан с работой Yang et al. *RNN-Stega: Linguistic Steganography Based on Recurrent Neural Networks*.

Для практического анализа использовалась реализация из репозитория:

`https://github.com/harvardnlp/NeuralSteganography`

## 4.2. Принцип работы

В отличие от Bins, код Хаффмана учитывает текущее распределение вероятностей следующего токена.

На каждом шаге:

1. выбирается множество наиболее вероятных токенов;
2. по их вероятностям строится дерево Хаффмана;
3. более вероятным токенам соответствуют короткие двоичные коды, менее вероятным — более длинные;
4. секретные биты задают путь по дереву и определяют токен.

Декодер строит то же дерево по той же модели и контексту и по принятому токену восстанавливает двоичный код.

## 4.3. Значение для исследования

По сравнению с Bins метод лучше учитывает вероятности языковой модели и обычно меньше искажает генерацию.

Однако вероятности, задаваемые двоичным деревом, имеют специальную дискретную форму и в общем случае не совпадают с исходными вероятностями языковой модели точно.

Код Хаффмана является удобным промежуточным методом между фиксированными корзинами и арифметическим кодированием.

## 4.4. Ограничения реализации

Практическая реализация имеет те же исторические ограничения по GPT-2 и старому интерфейсу модели, что и Bins.

Кроме того, расчет расхождения распределений необходимо вынести в общий модуль метрик, поскольку исходный код создавался для конкретного эксперимента.

## 4.5. Решение

**Код Хаффмана включается в основной набор.**

Основной управляющий параметр связан с размером множества токенов, по которому строится дерево.

# 5. Арифметическое кодирование

## 5.1. Исходная работа и реализация

Основным источником является работа Ziegler, Deng и Rush *Neural Linguistic Steganography* (2019).

Репозиторий:

`https://github.com/harvardnlp/NeuralSteganography`

является основной открытой реализацией предложенного в работе метода.

## 5.2. Принцип работы

Секретная битовая последовательность интерпретируется как число внутри текущего числового диапазона.

Распределение вероятностей следующего токена:

\[
p_1,p_2,\ldots,p_n
\]

используется для разбиения этого диапазона на подынтервалы, размеры которых пропорциональны вероятностям токенов.

Токен выбирается по тому, в какой подынтервал попала секретная точка. После выбора токена диапазон сужается, а однозначно определившаяся часть старших бит считается переданной.

Декодер последовательно воспроизводит те же подынтервалы и восстанавливает секрет.

## 5.3. Значение для исследования

Арифметическое кодирование является одним из центральных методов выбранного набора.

В идеальной математической постановке оно позволяет согласовать вероятность выбора токена с вероятностью языковой модели значительно точнее, чем Bins и код Хаффмана.

Поэтому метод особенно важен для проверки того, сохраняются ли теоретические свойства после перехода к реальной реализации.

На результат могут влиять:

- конечная вычислительная точность;
- округление границ интервалов;
- ограничение множества допустимых токенов;
- порядок сортировки;
- токенизация;
- различия вычислений кодера и декодера.

## 5.4. Состояние репозитория

В 2025 году часть кода была обновлена для более современных версий библиотек. Тем не менее в реализации остаются предположения, связанные с GPT-2 и его токенизатором.

Также в исходном коде температура и ограничение множества кандидатов фактически входят внутрь метода. В общем экспериментальном стенде такие операции должны выполняться до стегокодера и входить в определение эталонного распределения.

## 5.5. Решение

**Арифметическое кодирование включается в основной набор с высоким приоритетом.**

Оно будет использоваться как:

- основной исторический интервальный метод;
- точка сравнения для Bins и кода Хаффмана;
- объект исследования влияния конечной вычислительной точности;
- предшественник современных схем диапазонного кодирования.

# 6. ADG

## 6.1. Исходная работа и репозиторий

ADG — адаптивная динамическая группировка — предложен Zhang et al. в работе *Provably Secure Generative Linguistic Steganography* (2021).

Авторский репозиторий:

`https://github.com/Mhzzzzz/ADG-steganography`

содержит основной алгоритм встраивания, собственную рекуррентную языковую модель и код расчета нескольких показателей.

## 6.2. Принцип работы

ADG развивает идею Bins, но строит группы токенов заново на каждом шаге.

Алгоритм:

1. получает текущее распределение токенов;
2. определяет, на сколько групп его можно разделить;
3. формирует \(2^b\) групп с близкими суммарными вероятностями;
4. читает \(b\) секретных бит;
5. выбирает соответствующую группу;
6. нормализует вероятности внутри группы;
7. при необходимости повторяет процедуру рекурсивно;
8. выбирает итоговый токен.

Если группы имели бы строго одинаковую вероятность, выбор группы равномерными секретными битами не менял бы исходное распределение. На практике из-за дискретности токенов группы удается сбалансировать только приближенно.

## 6.3. Значение для исследования

ADG представляет отдельное семейство методов — адаптивную группировку.

По сравнению с Bins он лучше учитывает текущее распределение и позволяет уменьшить искажение.

Особенно полезно, что в авторском коде отдельно восстанавливается фактическое распределение, создаваемое ADG, и рассчитывается его KL-дивергенция относительно исходного распределения модели.

Это делает ADG удобным объектом для проверки разницы между теоретической идеей и реальным дискретным разбиением.

## 6.4. Ограничения реализации

Исходная реализация использует собственную словоуровневую рекуррентную языковую модель. Поэтому переносить необходимо сам алгоритм группировки, а не весь программный стек.

В репозитории отсутствует готовый декодер. Его потребуется реализовать самостоятельно.

Также в функции выбора ближайшей группы обнаружено подозрительное сравнение, которое необходимо проверить по публикации и на искусственных примерах до использования реализации как эталонной.

## 6.5. Решение

**ADG включается в основной набор.**

Основной риск адаптации — необходимость собственного декодера и дополнительная проверка корректности группировки.

# 7. Discop

## 7.1. Исходная работа и репозиторий

Discop предложен Ding et al. в работе *Discop: Provably Secure Steganography in Practice Based on “Distribution Copies”* (2023).

Авторский репозиторий:

`https://github.com/comydream/Discop`

содержит реализацию для нескольких типов данных. Для данной работы используется текстовая часть.

## 7.2. Принцип работы

Метод строит несколько представлений одного и того же распределения вероятностей.

В упрощенном виде исходное распределение можно представить как разбиение числового интервала на участки. Затем создается сдвинутая копия этого же разбиения.

Для одного и того же случайного значения две копии могут давать:

- один и тот же токен;
- разные токены.

Если токены различаются, секретный бит выбирает одну из копий и определяет следующий токен. Если токены совпадают, на этом уровне бит передать нельзя.

Для повышения эффективности Discop рекурсивно разлагает многозначное распределение через бинарное дерево.

## 7.3. Значение для исследования

Discop использует иной принцип, чем Bins, код Хаффмана и ADG.

В теоретической постановке он стремится сохранить исходное распределение токенов и одновременно приблизить скорость передачи к доступной энтропии.

Поэтому метод является важной современной точкой сравнения с арифметическим кодированием и RRC.

## 7.4. Состояние реализации

Авторский репозиторий содержит:

- кодер;
- декодер;
- пример полного цикла;
- обычную генерацию для сравнения;
- пакетные эксперименты;
- расчет ряда статистик.

Ядро метода достаточно хорошо отделено от конкретной языковой модели, что упрощает адаптацию.

## 7.5. Важное ограничение

В исходном коде поле KL-дивергенции фактически не рассчитывается: в него записывается ноль, соответствующий теоретическому свойству метода.

Поэтому это значение нельзя использовать как экспериментальное подтверждение отсутствия искажения.

В общей инфраструктуре KL-дивергенция и расстояние полной вариации должны измеряться независимо.

## 7.6. Решение

**Discop включается в основной набор с высоким приоритетом.**

Преимущества для исследования:

- современный метод с формальными свойствами сохранения распределения;
- готовый кодер и декодер;
- умеренная сложность адаптации;
- возможность сравнить теоретическое нулевое и фактически измеренное искажение.

# 8. RRC

## 8.1. Исходная работа и репозиторий

RRC — диапазонное кодирование со случайным вращением — предложен Ruiyi Yan и Yugo Murawaki в работе *Efficient Provably Secure Linguistic Steganography via Range Coding* (2026).

Авторский репозиторий:

`https://github.com/ryehr/RRC_steganography`

содержит кодер, декодер, отдельную проверку полного цикла и пакетный режим генерации.

## 8.2. Принцип работы

Секретное сообщение длины \(l\) бит представляется целым числом внутри диапазона:

\[
[0,2^l).
\]

На каждом шаге диапазон делится между токенами пропорционально их вероятностям.

Главное отличие RRC от обычного диапазонного кодирования состоит в дополнительном псевдослучайном вращении секретной точки внутри текущего интервала.

Перед выбором токена точка сдвигается на псевдослучайную величину. После выбора токена используется соответствующий подынтервал.

Декодер воспроизводит те же распределения и те же псевдослучайные сдвиги, после чего в обратном порядке восстанавливает исходную точку и секретные биты.

## 8.3. Значение для исследования

RRC является одним из наиболее важных современных методов в выбранном наборе.

Он заявляет почти полное использование доступной энтропии при сохранении входного распределения.

Кроме того, реализация позволяет исследовать влияние целого набора технических факторов:

- вычислительной точности;
- дискретности генератора псевдослучайных чисел;
- порядка сортировки токенов;
- ограничения множества токенов;
- повторной токенизации текста;
- воспроизводимости вычислений кодера и декодера.

Это делает RRC особенно полезным для исследования зависимости результатов от особенностей программной реализации.

## 8.4. Эталонное распределение

Если RRC работает только с несколькими наиболее вероятными токенами, вероятности внутри этого множества нормализуются заново.

Следовательно, свойство сохранения распределения относится именно к распределению после общего усечения.

Поэтому ограничение множества токенов должно выполняться до стегокодера и входить в определение эталонного распределения.

## 8.5. Надежность извлечения

В репозитории есть проверка полного цикла, но она передает декодеру непосредственно идентификаторы токенов.

В реальном текстовом канале возникает дополнительный этап:

\[
\text{токены}
\rightarrow
\text{текст}
\rightarrow
\text{повторная токенизация}
\rightarrow
\text{декодер}.
\]

Эта операция не всегда сохраняет исходную последовательность токенов.

Поэтому необходимо отдельно измерять надежность:

1. при передаче исходных идентификаторов токенов;
2. после преобразования в текст и повторной токенизации.

## 8.6. Вычислительная точность

В исходной реализации используется фиксированная точность десятичной арифметики.

Для коротких сообщений этого достаточно, но при увеличении длины секрета фиксированная точность может становиться недостаточной.

Поэтому точность следует сделать отдельным параметром и проверить ее влияние на:

\[
KL,\ TVD,\ \text{долю ошибок извлечения}.
\]

## 8.7. Решение

**RRC включается в основной набор с очень высоким приоритетом.**

Он будет использоваться как основной современный метод, ориентированный на сохранение распределения и эффективное использование энтропии.

# 9. DAIRstega

## 9.1. Исходная работа и репозиторий

DAIRstega предложен Yihao Wang et al. в работе *Dynamically Allocated Interval-Based Generative Linguistic Steganography with Roulette Wheel*.

Авторский репозиторий:

`https://github.com/WangYH-BUPT/DAIRstega`

содержит актуальную реализацию на PyTorch для LLaMA 2, готовые наборы стеготекстов и код вспомогательной оценки.

## 9.2. Принцип работы

Метод использует кодовое пространство размера:

\[
2^\alpha.
\]

Каждому токену назначается целочисленный интервал, размер которого зависит от вероятности токена:

\[
n_i \propto p_i^\beta.
\]

Параметр \(\alpha\) определяет размер кодового пространства, а \(\beta\) управляет тем, насколько сильно размер интервала зависит от вероятности языковой модели.

Секретное число выбирает интервал, а значит и следующий токен. После этого общий двоичный префикс границ интервала считается переданной частью секрета.

## 9.3. Значение для исследования

DAIRstega полезен тем, что его параметры непосредственно формируют разные рабочие точки.

Изменение \(\alpha\) и \(\beta\) позволяет управлять компромиссом:

\[
\text{емкость}
\leftrightarrow
\text{качество}
\leftrightarrow
\text{искажение распределения}.
\]

В отличие от Discop и RRC, метод не обязан стремиться к точному сохранению распределения. Поэтому он дает важный контраст между «сохранить распределение» и «допустить контролируемое отклонение ради большей емкости».

## 9.4. Ограничения реализации

Код привязан к LLaMA 2 и содержит модельно-зависимые идентификаторы токенов и правила остановки генерации.

Главное ограничение — отсутствие готового декодера.

Для включения метода в массовые эксперименты потребуется реализовать обратную процедуру и подтвердить надежное восстановление секрета.

Также исходные метрики не совпадают с определениями, принятыми для общего стенда. Например, емкость считается в битах на слово, хотя сам метод работает с токенами, а KL-дивергенция оценивается по частотам слов в готовых корпусах.

## 9.5. Решение

**DAIRstega включается в основной рабочий набор.**

При этом интеграционный риск выше, чем у Discop и RRC. Условием полноценного включения в масштабные эксперименты является успешная реализация декодера.

# 10. Сравнение выбранных методов

Выбранные методы представляют несколько разных классов.

## 10.1. Простые базовые методы

**Bins** и **код Хаффмана** нужны как понятные исторические точки отсчета.

Bins использует фиксированное разбиение словаря и ожидаемо сильнее искажает распределение.

Код Хаффмана уже учитывает текущее распределение, но его двоичная структура не позволяет точно воспроизвести произвольные вероятности.

## 10.2. Интервальное кодирование

**Арифметическое кодирование** представляет более точный способ согласовать выбор токена с вероятностями модели и является важной теоретической точкой сравнения.

## 10.3. Адаптивная группировка

**ADG** представляет отдельное семейство, в котором группы токенов строятся заново на каждом шаге.

## 10.4. Методы сохранения распределения

**Discop** и **RRC** стремятся сохранять эталонное распределение, но используют разные механизмы.

Discop кодирует секрет через выбор копии распределения.

RRC использует диапазонное кодирование с псевдослучайным вращением.

## 10.5. Управляемый компромисс

**DAIRstega** позволяет явно менять степень отклонения от исходного распределения и тем самым формировать разные рабочие точки по емкости и скрытности.

# 11. Дополнительно изученные методы и репозитории

В ходе первого этапа были рассмотрены и другие открытые проекты. Они сохраняют научную ценность, но на текущем этапе не включаются в основной набор.

## 11.1. iMEC

Репозиторий:

`https://github.com/schroederdewitt/perfectly-secure-steganography`

содержит реализацию метода минимальной энтропийной связи.

Метод важен теоретически, но текущая реализация имеет высокую вычислительную стоимость и использует устаревший программный стек. Кроме того, в коде выявлено несколько несогласованностей.

Поэтому iMEC целесообразно оставить как резервный метод, если основной набор будет реализован раньше запланированного.

## 11.2. Calgacus

Репозиторий:

`https://github.com/hodgesmr/calgacus-mlx`

решает несколько другую задачу.

Секретом является содержательный текст, а не равномерная битовая последовательность. Метод переносит ранги токенов секретного текста в распределение текста-носителя.

Для прямого сравнения с основным набором потребовалось бы дополнительное преобразование битов в текст, что изменило бы исходную постановку.

Также текущая реализация рассчитана на MLX и устройства Apple.

Поэтому Calgacus не включается в общий эксперимент.

## 11.3. `agent-stego`

Репозиторий:

`https://github.com/onblueroses/agent-stego`

содержит качественную реализацию конечного диапазонного кодирования с фиксированной секретной точкой и полезные инженерные решения по проверке корректности и построению выборок.

Однако это не основной авторский репозиторий одного из выбранных опубликованных методов. Проект целесообразно использовать как вспомогательный источник идей для общей инфраструктуры.

## 11.4. `steganographic-evals`

Репозиторий:

`https://github.com/arturzolkowski/steganographic-evals`

исследует скрытые каналы, которые сама языковая модель создает по текстовой инструкции.

Такая постановка отличается от рассматриваемой в работе токеновой стеганографии, где отдельный алгоритм получает распределение следующего токена и секретные биты.

Поэтому проект может быть полезен для идей оценки, но не включается как отдельный стегометод.

## 11.5. Репозитории стегоанализа и обзора

`CAU-Tstega/Text-steganalysis` содержит несколько классических нейросетевых стегодетекторов. Он будет полезен при проектировании оценки эмпирической обнаружимости, но не является методом встраивания.

`comydream/provably-secure-steganography` представляет библиографическую карту работ по доказуемо безопасной стеганографии и не содержит реализации алгоритмов.

# 12. Требования к адаптированным реализациям

Проведенный анализ показывает, что сравнивать методы непосредственно в их исходных репозиториях нельзя: внешние условия и определения метрик слишком различаются.

Поэтому каждый метод должен быть перенесен в единый программный интерфейс.

Кодер должен получать:

\[
P_{\text{ref}}
+
\text{секретные биты}
+
\text{состояние метода}
\rightarrow
\text{следующий токен}.
\]

Декодер должен получать:

\[
P_{\text{ref}}
+
\text{наблюдаемый токен}
+
\text{состояние метода}
\rightarrow
\text{восстановленные биты}.
\]

Языковая модель и токенизатор должны находиться вне конкретного стегометода.

## 12.1. Единое эталонное распределение

Сначала языковая модель формирует вероятности следующего токена.

Затем к ним применяются общие настройки обычной генерации.

Полученное распределение определяется как:

\[
P_{\text{ref}}.
\]

Только после этого оно передается стегокодеру.

Это позволяет отделить влияние общих настроек генерации от дополнительного изменения, которое вносит стегометод.

## 12.2. Единые секретные последовательности

Все методы должны получать один и тот же заранее сформированный набор равномерных битовых последовательностей.

Для каждого запуска необходимо сохранять:

- идентификатор секрета;
- длину секрета;
- исходные биты;
- восстановленные биты.

Если метод не смог передать сообщение, случай должен фиксироваться как отказ. Нельзя заменять его новым случайным секретом.

## 12.3. Проверка полного цикла

До масштабного запуска каждый метод должен пройти автоматическую проверку:

\[
\text{секрет}
\rightarrow
\text{кодер}
\rightarrow
\text{стеготекст}
\rightarrow
\text{декодер}
\rightarrow
\text{восстановленный секрет}.
\]

Для ADG и DAIRstega декодер потребуется реализовать самостоятельно.

Для методов, чувствительных к токенизации, необходимо отдельно проверять:

1. извлечение по исходным идентификаторам токенов;
2. извлечение после преобразования в текст и повторной токенизации.

## 12.4. Общие метрики

Основные показатели должны рассчитываться общей инфраструктурой, а не кодом отдельных репозиториев.

Минимальный набор:

### Емкость

\[
\text{бит/токен}
=
\frac{\text{число успешно переданных бит}}
{\text{число сгенерированных токенов}}.
\]

### Искажение распределения

KL-дивергенция и расстояние полной вариации между индуцированным и эталонным распределениями.

### Эффективность использования энтропии

Отношение числа переданных бит к доступной энтропии эталонного распределения.

### Качество текста

Отрицательное логарифмическое правдоподобие и перплексия относительно общей модели оценки.

### Надежность

- доля полностью успешных извлечений;
- доля ошибочных бит;
- доля отказов и рассинхронизаций.

### Вычислительная эффективность

- время встраивания;
- время извлечения;
- время на токен;
- скорость передачи секретных бит.

### Эмпирическая обнаружимость

Для одинаковых выборок обычной и стегографической генерации обучается стегодетектор.

Основной показатель:

\[
ROC\text{-}AUC.
\]

| Bins | есть | есть | низкая | включить |

# 14. Итоговый выбор методов

По результатам анализа открытых репозиториев для основной экспериментальной части фиксируется следующий набор:

\[
\boxed{
\text{Bins, Huffman, Arithmetic Coding, ADG, Discop, RRC, DAIRstega}
}
\]

Выбор обоснован тем, что эти методы представляют разные этапы и разные принципы развития генеративной лингвистической стеганографии:

\[
\text{фиксированная группировка}
\rightarrow
\text{код Хаффмана}
\rightarrow
\text{арифметические интервалы}
\rightarrow
\text{адаптивная группировка}
\rightarrow
\text{копии распределения}
\rightarrow
\text{диапазонное кодирование с вращением}
\rightarrow
\text{динамически распределяемые интервалы}.
\]

Таким образом, выбранный набор содержит:

- простые исторические методы;
- вероятностные методы;
- современные методы с формальными свойствами сохранения распределения;
- метод с управляемым компромиссом между емкостью и искажением.

Этого достаточно для проверки основной гипотезы работы: методы генеративной лингвистической стеганографии необходимо сравнивать в одинаковых контролируемых условиях и рассматривать как множества рабочих точек, а не как отдельные опубликованные конфигурации.
