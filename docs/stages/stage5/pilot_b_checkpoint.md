## 3. Надежность восстановления секрета

Статус `ok` означает только то, что программа завершила запуск без исключения. Он не гарантирует точное восстановление секрета.

Фактический результат Pilot B:

| Метод | Всего | Точно | Завершено, но секрет неверен | Ошибка декодирования | Доля точных |
|---|---:|---:|---:|---:|---:|
| Bins | 96 | 51 | 45 | 0 | 53.1% |
| Huffman | 96 | 67 | 9 | 20 | 69.8% |
| Arithmetic Coding | 144 | 134 | 7 | 3 | 93.1% |
| ADG | 24 | 23 | 1 | 0 | 95.8% |
| Discop | 24 | 22 | 0 | 2 | 91.7% |
| DAIRstega | 120 | 107 | 0 | 13 | 89.2% |
| **Итого** | **504** | **404** | **62** | **38** | **80.2%** |

Таким образом:

- 404/504 запуска восстановили секрет точно;
- 62 запуска завершились без программной ошибки, но имели `roundtrip_exact=false`;
- 38 запусков завершились ошибкой во время декодирования;
- всего 100/504 запусков не дали точного восстановления секрета по полному текстовому пути.

## 4. Распределение ошибок декодирования

38 `hard failure` распределились так:

- Huffman — 20;
- DAIRstega — 13;
- Arithmetic Coding — 3;
- Discop — 2;
- Bins — 0;
- ADG — 0.

В исходном Pilot B эти ошибки возникали после того, как сгенерированные токены были преобразованы в текст, а затем текст был повторно токенизирован на стороне декодирования.

На момент завершения Pilot B причина этих 100 неточных результатов еще не считалась доказанной. Поэтому перед выбором рабочих точек Stage 6 был проведен отдельный Decoder Audit.

## 5. Итог Decoder Audit

Decoder Audit завершен.

Полный отчет:

`docs/stages/stage5/decoder_audit_report.md`.

Основные результаты:

1. Прямое декодирование токенов отправителя дало точное восстановление секрета во всех **504/504** конфигурациях Pilot B.
2. Все шесть декодеров прошли независимую проверку: **3533 проверки, 0 расхождений**.
3. Все **62/62** запуска с `roundtrip_exact=false`, которые завершились без программной ошибки, связаны с изменением последовательности токенов после `token IDs → text → retokenization`.
4. Все **38/38** исходных `hard failure` воспроизведены после того же текстового канала на детерминированно восстановленных последовательностях отправителя. Во всех случаях совпали тип и текст исходной ошибки.

Для 38 `hard failure` сохраняется ограничение: исходные `sender_token_ids` не были сохранены в Pilot B. Поэтому проверка основана на детерминированно восстановленной последовательности, а не на буквальном повторе потерянных исходных токенов.

Итоговый вывод: аудит не выявил ошибок в декодерах. Причина 100 неточных результатов Pilot B локализована в текстовом канале между исходной последовательностью токенов и повторной токенизацией полученного текста.

При этом сами 100 неточных результатов остаются частью результатов Pilot B. Основная проверка надежности бенчмарка по-прежнему включает полный путь через обычный текстовый канал.
