# Stage 5 — калибровка размера секрета RRC перед Stage 6

**Статус:** завершена. Все 32 запуска выполнены. Для Stage 6 выбран `payload_bits=1024`. Итоговое обоснование находится в `docs/stages/stage5/rrc_payload_calibration_report.md`.

## 1. Цель

Численная реализация RRC уже проверена: накопительные границы строятся в Decimal, обе KL конечны, а прежняя потеря малых положительных интервалов устранена.

Последний отдельный вопрос RRC перед фиксацией Stage 6 — выбрать размер фиксированного секрета.

Проверяются четыре значения:

```text
128 бит
256 бит
512 бит
1024 бит
```

Это не четыре разные рабочие точки RRC по смыслу алгоритма. Меняется только длина сообщения, которое RRC должен полностью передать.

## 2. Почему нужен отдельный запуск

Для потоковых методов в Pilot B было задано 256 токенов-носителей, после чего измерялось число переданных бит.

RRC работает в другом режиме:

```text
фиксированный секрет → столько токенов, сколько требуется для его передачи
```

Поэтому размер секрета нужно выбрать отдельно. Слишком короткий секрет даст очень короткие тексты и сильнее проявит случайный разброс между отдельными генерациями. Слишком длинный секрет увеличит длину текста и вероятность встретить изменение токеновой последовательности после преобразования через текст.

Цель калибровки — найти размер, при котором длина текста остаётся удобной для основного сравнения и результаты достаточно устойчивы.

## 3. Постоянные настройки

Во всех запусках фиксируются:

```text
model = meta-llama/Llama-3.2-3B
precision_margin = 40
verify_termination = true
temperature = 1.0
top_k = null
top_p = 1.0
4 промпта × 2 повтора
max_carrier_tokens = 2048
```

Используется исправленная реализация:

```text
stage5-rrc-decimal-boundaries-v2
```

## 4. Парность запусков

Для каждого размера секрета используется один и тот же:

```text
sweep_id = stage5-rrc-payload-calibration-llama-v1
```

Также совпадают `prompt_id`, `replicate_id` и `secret_id`.

В текущей инфраструктуре ключ RRC выводится из `sweep_id`, `replicate_id` и идентификатора метода. Поэтому для одной пары `prompt × replicate` все четыре размера секрета используют одинаковый ключ RRC.

Это позволяет сравнивать размеры секрета в максимально близких условиях.

Всего планируется:

```text
4 payload × 4 prompts × 2 replicates = 32 запуска
```

## 5. Конфигурации

Используются четыре manifest-файла с общим `sweep_id`:

```text
configs/pilots/stage5/rrc_payload_calibration_128_llama.json
configs/pilots/stage5/rrc_payload_calibration_256_llama.json
configs/pilots/stage5/rrc_payload_calibration_512_llama.json
configs/pilots/stage5/rrc_payload_calibration_1024_llama.json
```

Каждый файл содержит 8 запусков. Общий журнал всех четырёх частей записывается в:

```text
results/stage5/sweeps/stage5-rrc-payload-calibration-llama-v1/execution.jsonl
```

## 6. Что сравнивается

Для каждого размера секрета рассматриваются:

- число токенов-носителей;
- BPT;
- эффективность использования энтропии;
- обе KL и TVD;
- PPL;
- время работы;
- точность полного восстановления секрета;
- BER;
- сохранение токеновой последовательности после преобразования `token IDs → text → retokenization`.

Численная корректность RRC и надёжность текстового канала рассматриваются отдельно. Изменение токенов после текстового преобразования само по себе не считается численной ошибкой RRC.

## 7. Ориентир по длине текста

256 токенов из Pilot B используется как удобный ориентир при сравнении длины текста. Это не жёсткое правило выбора.

Сводка отдельно покажет, какой размер секрета даёт медианную длину текста, наиболее близкую к 256 токенам.

Окончательный payload выбирается только после рассмотрения вместе:

- длины текста;
- разброса BPT;
- надёжности полного текстового цикла;
- стабильности токенизации;
- вычислительной стоимости.

## 8. Итоговая сводка

После завершения всех 32 запусков используется:

```text
scripts/summarize_stage5_rrc_payload_calibration.py
```

Результат сохраняется в:

```text
results/stage5/rrc_payload_calibration/summary.json
```

После этой калибровки можно будет зафиксировать единственный размер фиксированного секрета RRC для Stage 6.
