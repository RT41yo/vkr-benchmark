# Этап 4 — протокол проверки воспроизводимости Discop

## Цель проверки

Проверка Discop должна подтвердить четыре вещи: соответствие нашей реализации алгоритму авторов, корректность полного цикла передачи секрета, воспроизведение характерного поведения метода на выбранной языковой модели и независимое построение распределения `Q_stego` для расчета KL-дивергенции и TVD.

Зафиксированная авторская версия: `comydream/Discop@3c3a10099a242eae405b49cc4d09fba1abb148ad`.

## 1. Соответствие алгоритмического ядра

Сначала наша реализация сравнивается с независимой реализацией на Python, повторяющей логику функций `cy_encode_step` и `cy_decode_step` из авторского кода. Для обеих реализаций используются одинаковые распределения вероятностей, секретные биты и последовательности случайных чисел.

Должны совпадать выбранный токен, число встроенных битов, восстановленные биты и число обращений к генератору случайных чисел.

Дополнительно, если авторский модуль успешно собирается, выполняется прямое сравнение с неизмененным `stega_cy.pyx`. Для его сборки используется `Cython==0.29.37`, совместимый с Python 3.12. Cython требуется только для проверки авторской реализации и не является зависимостью основной реализации Discop в бенчмарке.

## 2. Полный цикл передачи секрета

Проверяется полный путь

`secret → Discop → token IDs → text → retokenization → Discop decoder → recovered secret`.

Перед декодированием текст повторно преобразуется в токены обычным токенизатором модели. Внутренние токены отправителя декодеру напрямую не передаются.

## 3. Проверка характерного поведения

На Llama-3.2-3B выполняется генерация по 100 токенов-носителей при `top-p = 0.80, 0.92, 0.95, 0.98, 1.00`.

`top-p` относится к общей политике построения `P_reference` и применяется до вызова Discop. Сам метод получает уже окончательно сформированное `P_reference` и не выполняет дополнительного ограничения распределения.

Для каждой точки фиксируются BPT, энтропия `P_reference`, эффективность использования энтропии, сохранность последовательности токенов после текстового канала и точность восстановления секрета.

Эта проверка считается воспроизведением характерного поведения, а не прямым численным воспроизведением таблицы статьи, поскольку в публикации использовались GPT-2 и контексты IMDb.

## 4. Независимый расчет `Q_stego`

Для Discop в бенчмарке не используется готовое допущение `Q_stego = P_reference`. На каждом шаге `Q_stego` строится явно отдельным вычислительным путем, независимым от выбранных при кодировании секретных битов и конкретной последовательности случайных чисел.

Вычислитель самостоятельно строит дерево Хаффмана с теми же правилами упорядочивания, после чего для каждого внутреннего узла разбивает диапазон случайного указателя на участки, где выбор обеих распределительных копий неизменен. Если две копии выбирают разные ветви, каждая получает вес `1/2`, соответствующий равновероятным секретным битам. Полученная вероятность рекурсивно распространяется до листьев дерева, формируя полный массив `Q_stego` по словарю.

После этого `Q_stego` передается в общий модуль метрик как явный массив вероятностей. Оба направления KL-дивергенции и TVD рассчитываются теми же функциями, что и для других методов. Для обычных запусков Discop используется режим `exact_enumeration` и источник `independent_enumeration`; сертификат равенства `Q=P` не применяется.

Перед принятием такого режима выполнена отдельная проверка явного расчета на 133 синтетических распределениях и 25 реальных `P_reference` от Llama-3.2-3B. При расчете метрик канонический FP32-вектор `P_reference` переводится в FP64 и делится на его фактическую сумму, чтобы удалить только численный остаток хранения и получить корректно нормированное распределение. Эта операция применяется общим модулем метрик ко всем методам с явным `Q_stego`; она не меняет поддержку распределения и не является дополнительной политикой генерации.

Полный `Q_stego` нужен только для исследовательских метрик и не участвует в выборе токена Discop. Поэтому время его построения, как и время расчета KL/TVD, относится к измерительному контуру бенчмарка и исключается из показателей скорости метода. В `stego_algorithm_ms` учитываются только операции, необходимые самому Discop для встраивания и извлечения секрета. Стоимость расчета метрик сохраняется отдельно как `metric_instrumentation_ms`.

## Ориентир из публикации

В статье Ding et al. (IEEE S&P 2023) для Discop на GPT-2 сообщается эффективность использования энтропии около 92–95% при нескольких значениях `top-p`, а KLD приводится равным нулю. Эти значения используются как ориентир для характерного поведения метода, а не как целевые числа для Llama-3.2-3B.

## Условия успешного завершения

Discop считается успешно проверенным на Этапе 4, если модульные и регрессионные тесты проходят без ошибок, сравнение с авторским алгоритмом не выявляет расхождений, полный текстовый цикл восстанавливает секрет, характерный запуск демонстрирует ожидаемую эффективность использования энтропии, а независимый явный расчет `Q_stego` проходит на синтетических и реальных распределениях без систематического расхождения с `P_reference`.
