# Этап 4 — итерация 8: ADG smoke и paper-vs-repository conformance

## 1. Real-LM smoke на Llama-3.2-3B

Пользовательский запуск normalized ADG на основной модели успешно прошёл оба уровня: отдельный E2E smoke и unified experiment pipeline.

Условия:

- модель: `meta-llama/Llama-3.2-3B`;
- revision: `13afe5124825b4f3751f836b40dafda64c1ed062`;
- 16 токенов-носителей;
- `secret_id = 000001`;
- `method.random_seed = 42`;
- общий `top-k = None`, `top-p = 1.0`.

Наблюдаемый результат:

- встроено 71 бит;
- BPT = 4.4375;
- `BER = 0`;
- sender/receiver token IDs совпали полностью;
- `roundtrip_exact = True`;
- `decoder complete = True`;
- `q_mode = exact_enumeration`;
- `q_source = independent_enumeration`;
- mean `D_KL(P_ref || Q) = 0.009492` бит/токен;
- mean `D_KL(Q || P_ref) = 0.009787` бит/токен;
- mean TVD = 0.026408;
- max `D_KL(P_ref || Q) = 0.060777`;
- max TVD = 0.140274;
- run id: `2ac7e3612ed548d7`.

Таким образом, первый интеграционный gate пройден: ADG работает в общей архитектуре, полный секрет восстанавливается, а независимый explicit-`Q` показывает ожидаемое малое, но ненулевое искажение распределения.

## 2. Почему entropy utilization получился 105.035%

В smoke-run отношение `payload_bits / sum H(P_ref)` равно `71 / 67.596372 = 1.050352`.

Это не трактуется как нарушение информационно-теоретического предела. В benchmark знаменатель — энтропия **эталонного** `P_ref`, тогда как ADG фактически сэмплирует из `Q_stego`, которое здесь не совпадает с `P_ref`. Кроме того, это отношение рассчитано по одной короткой реализованной траектории из 16 токенов, а не как математическое ожидание по бесконечному ансамблю.

Поэтому значение выше 100% для отдельного ADG-run допустимо как диагностическая характеристика. Его нельзя интерпретировать как «ADG без искажения использовал больше энтропии, чем было доступно в P_ref». Наоборот, dual-KL/TVD прямо показывают, что распределение было изменено.

## 3. Связь со статьёй

Smoke не является прямым численным воспроизведением Table 1: статья использует word-level LSTM и три исторических корпуса, а benchmark — Llama subword tokens и собственный `P_ref`.

Тем не менее качественное поведение совпадает с публикационным ориентиром: высокая embedding rate сочетается с малым, но ненулевым `D_KL(P_LM || q)`.

Точное publication-characteristic сравнение выполняется отдельным probe и не должно выводиться из одного 16-токенного smoke-run.

## 4. Следующий gate

После успешного smoke выполняется paper-vs-repository conformance:

1. независимая Algorithm-1 реализация сравнивается с normalized ADG на синтетических распределениях;
2. отдельно строится literal-вариант публичного `near()`;
3. измеряется, как часто расхождение `anum - up` меняет итоговый `Q_stego`;
4. pinned авторский файл запускается напрямую только для подтверждения фактического поведения `near()` и little-endian helpers;
5. публичный код не модифицируется.

## 5. Synthetic paper-vs-repository conformance

Проверка на 132 синтетических распределениях завершилась `PASS`:

- normalized ADG vs независимая Algorithm-1 реализация: 0 расхождений;
- max `|Q_normalized - Q_paper| = 5.551e-17`;
- literal public-repository semantics изменила итоговый `Q` в 109/132 fixtures (82.6%);
- максимальный TVD между paper-faithful и literal-repository `Q` = 0.114661;
- диагностический пример для `target = 0.16`, кандидаты `[0.18, 0.11]`: статья выбирает `0.18`, literal `near()` — `0.11`.

Это не означает, что 82.6% реальных LM-шагов обязательно расходятся: fixture suite специально разнообразен и включает синтетические распределения. Число используется как conformance-диагностика, а не как оценка частоты ошибки на Llama.

Прямой запуск pinned `adg-stega.py` также завершён `PASS`: 5 `near()` cases, 0 расхождений author vs literal-repository, 1 расхождение author vs paper, 0 failures little-endian bit conversion, author checkout unchanged = True. Это подтверждает, что наблюдаемое расхождение действительно присутствует в исполняемом pinned публичном файле, а не возникло при нашей транскрипции. Следующий шаг — publication-characteristic probe относительно Table 1.
