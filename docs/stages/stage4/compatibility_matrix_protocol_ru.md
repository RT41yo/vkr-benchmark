# Stage 4 — протокол матрицы совместимости методов с моделями и токенизаторами

## Цель

Матрица отвечает только на технический вопрос: может ли каждый адаптированный метод корректно пройти полный цикл на каждой из двух выбранных модельно-токенизаторных пар в общей инфраструктуре бенчмарка.

Матрица **не является сравнительным экспериментом качества**. BPT, KL/TVD, PPL/NLL и скорость не используются для ранжирования методов или моделей. Сравнительные свипы и проверка устойчивости выводов на второй модели относятся к последующим этапам.

## Модели

- основная: Llama-3.2-3B, revision `13afe5124825b4f3751f836b40dafda64c1ed062`;
- резервная: Qwen3-4B-Base, revision `906bfd4b4dc7f14ee4320094d8b41684abff8539`.

Для Qwen общая инфраструктура до передачи `P_reference` стегометоду исключает output ID, не имеющие отображения в токенизаторе, и перенормирует распределение. Это модельно-токенизаторная адаптация общего уровня, а не специальное правило конкретного стегометода.

## Методы

Проверяются все семь методов текущего benchmark v0.3:

- Bins;
- Huffman;
- Arithmetic Coding;
- Discop;
- RRC;
- ADG;
- DAIRstega.

Используются уже зафиксированные рабочие параметры Stage 2–4. Для DAIRstega используется консервативная точка `alpha=8`, `beta=1.0`, method-local `top_k=100`. Для RRC используется фиксированный payload 64 бита с safety cap 128 carrier tokens; остальные методы используют 16 carrier tokens.

## Общие входные условия

Обе модели получают одинаковые:

- prompt: `The history of artificial intelligence began`;
- `secret_id = 000001`;
- common generation policy: `top_k = None`, `top_p = 1.0`.

Это короткий smoke-test одной фиксированной точки, а не статистическая оценка reliability.

## Проверки одной ячейки method × model

1. Модель и токенизатор загружаются через общий `HFCausalLMAdapter`.
2. Общая инфраструктура строит `V_allowed` и `P_reference` по тем же правилам, что и обычный benchmark.
3. Кодер формирует carrier без вызова `distribution_info()` — explicit Q и KL/TVD здесь намеренно не рассчитываются.
4. Секрет сначала восстанавливается непосредственно из исходных carrier token IDs.
5. Затем carrier проходит обязательный обычный текстовый канал `tokens → text → tokens`.
6. Проверяются точное восстановление token sequence и точное восстановление секретного payload после текстового канала.

Таким образом, матрица отдельно фиксирует algorithm/token-ID compatibility и tokenizer/text-transport compatibility.

## Статусы

`PASS` — direct secret round-trip, text token round-trip и text secret round-trip точны; модель не требует исключения output-only ID.

`PASS_WITH_ADAPTATION` — те же проверки точны, но общая инфраструктура должна исключить output ID модели, отсутствующие в токенизаторе, и перенормировать `P_reference`. Ожидаемый пример — Qwen3-4B-Base.

`FAIL` — хотя бы одна из обязательных проверок текущей ячейки не проходит или метод завершился исключением. JSON сохраняет отдельные флаги direct/text checks и diagnostic error, поэтому `FAIL` не смешивает алгоритмическую ошибку с проблемой текстового транспорта.

## Почему instrumentation отключена

Матрица не вызывает независимое построение полного `Q_stego`, KL/TVD, entropy или raw-LM NLL. Это особенно важно для ADG, где independent explicit-Q существенно дороже собственно стегокодирования. Совместимость должна измерять способность метода пройти полный цикл, а не стоимость дополнительных диагностических метрик.

Метрики распределения уже проверены отдельными reproducibility probes каждого метода и будут использоваться в сравнительных экспериментах последующих этапов.

## Фактический результат Stage 4

Реальный запуск на pinned checkpoints завершен успешно:

- Llama-3.2-3B: 7/7 `PASS`;
- Qwen3-4B-Base: 7/7 `PASS_WITH_ADAPTATION`;
- direct secret round-trip: 14/14;
- text token round-trip: 14/14;
- text secret round-trip: 14/14.

Qwen подтвердила ожидаемую архитектурную особенность: 267 output-only ID исключаются общей инфраструктурой до построения рабочего `P_reference`; после этой нормализации все семь методов работают без method-specific изменений.

Итоговый отчет: `docs/stages/stage4/compatibility_matrix_report_ru.md`.
