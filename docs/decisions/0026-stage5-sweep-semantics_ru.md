# ADR-0026: Семантика свипов Stage 5 — method-local points, внешние условия и calibration

**Статус:** принято для Stage 5  
**Ветка:** `stage5-pilot-sweeps`

## Контекст

Этап 5 должен определить рабочие диапазоны параметров методов и окончательный дизайн Stage 6. При этом семь подключенных методов устроены неодинаково: у Bins, Huffman, Arithmetic Coding и DAIRstega есть естественные управляющие параметры, а normalized ADG и Discop не имеют пользовательской ручки компромисса. У RRC есть параметры, часть которых относится к численной устойчивости и режиму завершения, а не к отдельному содержательному operating point.

Если смешать эти типы параметров, можно искусственно создать «точки метода», которые на самом деле являются разными внешними условиями эксперимента, и затем некорректно объединить их на одном Парето-фронте.

## Решение

### 1. Method-local operating point

Рабочая точка метода создается только изменением параметра, принадлежащего самому алгоритму и содержательно меняющего его режим работы.

На Stage 5 к таким параметрам относятся:

- Bins: `block_size`;
- Huffman: `bits_per_word`;
- Arithmetic Coding: `precision`, method-local `top_k`;
- DAIRstega: `alpha`, `beta`, `top_k`.

ADG и Discop в текущих normalized adapters не получают искусственных дополнительных параметров. Их основной normalized режим может состоять из одной operating point.

### 2. Общие внешние условия

`temperature`, common `top_k`, common `top_p`, модель, tokenizer, prompt set и общая политика формирования `P_reference` относятся к внешним условиям эксперимента.

Если, например, исследуется `top_p={0.95,0.98,1.0}`, одно и то же значение применяется ко всем сравниваемым методам. Результаты разных `top_p` не объединяются в один Парето-фронт как будто это точки одного и того же экспериментального условия.

### 3. RRC calibration

`precision_margin` и выбор fixed-payload длины для сопоставимой carrier length рассматриваются сначала как calibration, а не как семейство научных operating points.

Задача calibration:

- выбрать достаточный `precision_margin`, после которого дальнейшее увеличение не меняет корректность/результаты;
- подобрать fixed payload, при котором длина RRC carrier сопоставима по порядку с нормализованной длиной остальных методов;
- сохранить `verify_termination=true`.

После calibration Stage 6 получает один заранее зафиксированный normalized RRC regime, если данные не покажут необходимость иного решения.

### 4. Парето-анализ

Глобальный Парето-фронт строится по объединению рабочих точек всех методов **только внутри одного набора внешних условий**.

Отдельные условия, например Llama и Qwen либо два значения common `top_p`, дают отдельные фронты. Затем сравнивается устойчивость выводов между условиями.

### 5. Paired replicates

Один replicate означает новый `secret_id` и, для методов с внутренней случайностью/ключом, новый воспроизводимый method-randomness material. Один и тот же replicate используется парно для всех method/generation points, чтобы изменение параметра не смешивалось со сменой секрета.

Для Stage-5 sweep orchestration method randomness выводится из строки:

```text
VKR-BENCHMARK-STAGE5-v1|sweep=<sweep_id>|replicate=<replicate_id>|method=<method_id>|role=<random_seed|key>
```

- Bins, ADG -> `method.random_seed`;
- Discop, RRC -> `method.key`;
- Huffman, Arithmetic Coding, DAIRstega -> отдельная method RNG/key не задается.

Эта строка сохраняется в канонической run configuration, поэтому каждый запуск полностью воспроизводим.

## Следствия

1. Число рабочих точек у разных методов не обязано совпадать.
2. ADG/Discop не получают фиктивные ручки только ради красивой кривой.
3. `top_p` сначала калибруется как общее условие, затем фиксируется для main Stage-6 comparison.
4. RRC calibration не интерпретируется как доказательство trade-off curve RRC.
5. Stage-5 planner обязан разделять `generation_point_id` и `method_point_id`.
