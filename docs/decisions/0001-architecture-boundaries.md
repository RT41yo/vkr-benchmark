# ADR-0001: Границы базовых компонентов

Статус: принято для реализации этапа 2.

## Решение

Бенчмарк разделяется на независимые компоненты:

- `lm` — модель, токенизатор, KV-cache;
- `distributions` — построение канонического `P_reference`, порядок токенов и представление `Q_stego`;
- `randomness` — секрет, ключевая/методная случайность, control RNG;
- `methods` — только алгоритмика стегометода;
- `transport` — token IDs → text → token IDs;
- `metrics` — независимый расчет метрик;
- `runner` — orchestration encode/decode/control;
- `trace` — пошаговая диагностика;
- `storage` — сохранение run artifacts и summary.

## Причина

Такое разделение сохраняет семантику спецификации v0.1 и позволяет подключить Bins, Huffman, Arithmetic Coding, а затем ADG, Discop, RRC и DAIRstega без переноса ответственности между слоями.

Для Method adapter в коде используется более общий stateful lifecycle, чем минимальный концептуальный интерфейс v0.1. Сама спецификация v0.1 не изменяется; это уточнение зафиксировано для будущей v1.0 в отдельном документе замечаний.
