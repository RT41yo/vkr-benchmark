# ADR-0011. KL/TVD считаются общим metric layer по `P_reference` и `Q_stego`

## Контекст

Шаг 7.3 этапа 2 добавляет первый блок метрик, который непосредственно сравнивает
каноническое эталонное распределение языковой модели с распределением,
индуцированным стегометодом.

Спецификация v0.1 фиксирует направление KL:

\[
D_{KL}(P_{reference} \parallel Q_{stego})
\]

в битах на токен и запрещает скрытое epsilon-сглаживание. Если существует токен
с `P_reference(x) > 0` и `Q_stego(x) = 0`, KL данного шага должна быть `+inf`.
TVD определяется как

\[
\frac12 \sum_x |P_{reference}(x)-Q_{stego}(x)|.
\]

Bins, Huffman и Arithmetic Coding уже возвращают `DistributionInfo` с exact
explicit `Q_stego`, поэтому metric layer не должен реконструировать алгоритм
метода повторно.

## Решение

1. `metrics/distribution_distortion.py` является единственным общим местом
   вычисления KL/TVD.
2. Метрика получает канонический `ReferenceDistribution` и `DistributionInfo`,
   возвращенный adapter'ом на том же sender-side шаге.
3. Для `EXPLICIT_PROBABILITIES` сравниваются полные векторы одинакового размера.
4. Для `REFERENCE_EQUALITY_CERTIFICATE` KL и TVD равны нулю без материализации
   второй копии `P_reference`.
5. `q_mode=unavailable` не заменяется selected-token probability, epsilon-Q или
   другой surrogate-величиной: KL/TVD сохраняются как недоступные (`None`).
6. Нули `Q_stego` при положительном `P_reference` не сглаживаются и дают `+inf`.
7. На run-level сохраняются `q_mode`, KL mean/median/p95/max, число бесконечных и
   конечных KL-шагов, а также TVD mean/median/p95/max.
8. Если хотя бы один KL-шаг бесконечен, `kl_mean_bits = inf`.
9. Для p95 в программной реализации v0.2 используется **эмпирический
   nearest-rank percentile**. Это исключает неопределенную линейную интерполяцию
   между конечным значением и `+inf` и дает воспроизводимую статистику на малых
   pilot-run выборках.
10. `P_reference` не нормализуется заново и не меняется metric layer. Расчеты
    выполняются в FP64 поверх канонических FP32 вероятностей. Допускается только
    численная нормализация TVD ровно на границах `[0,1]` в пределах `1e-6`, чтобы
    поглотить FP32 storage roundoff; это не является probability smoothing.

## Почему KL/TVD считаются во время sender-side шага

`EncodeDecision` уже содержит соответствующее текущему префиксу `Q_stego`.
Вычисление scalar step-metrics сразу после решения позволяет не хранить на весь
run большие массивы `P` и `Q` размером порядка полного словаря. В результате
`StreamingEncodeResult` хранит только небольшие `StepDistributionDistortion`.
Полные распределения при необходимости могут быть добавлены позднее в DEBUG
trace, как и предусматривает спецификация.

## Ожидаемое поведение базовых методов

Для Bins и Huffman `Q_stego` имеет ограниченный support, тогда как
`P_reference` обычно положителен на значительно большем числе токенов. Поэтому
`D_KL(P_reference || Q_stego)` на большинстве/всех шагов ожидаемо равен `inf`.
Это корректный результат выбранного направления KL, а не ошибка реализации.

Arithmetic Coding также может иметь ограниченный method-internal candidate
support, поэтому конечность KL зависит от конкретной finite-precision partition
и внутреннего `top_k`. TVD при этом остается конечной в `[0,1]` и пригодна для
количественного сравнения даже при бесконечной KL.

## Последствия

- Bins/Huffman/Arithmetic используют один и тот же код метрик.
- Стегометод отвечает только за корректное описание своего `Q_stego`.
- Нельзя «улучшить» KL техническим epsilon-сглаживанием.
- Конвенцию p95 необходимо явно рассмотреть при подготовке specification v1.0.
