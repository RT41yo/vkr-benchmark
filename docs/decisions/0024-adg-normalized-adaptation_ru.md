# ADR-0024 — Нормализованная семантика ADG и расхождение `near()`

**Статус:** принято  
**Дата:** 2026-10-10

## Контекст

ADG описан в Zhang et al. (2021), *Provably Secure Generative Linguistic Steganography*. Для Этапа 4 зафиксирован авторский репозиторий `Mhzzzzz/ADG-steganography` на коммите `b4a7e802a97bc3a3b84d07e63f24627b16c51a10`.

Публикация задаёт в Algorithm 1 субоптимальное равновероятное разбиение: при заполнении очередной группы выбирается токен, **вероятность которого ближе всего к текущему остаточному значению** `epsilon`.

В публичном коде функция `near()` в последнем сравнении содержит выражение:

```python
if alist[bottom] - anum < anum - up:
```

где `up` — индекс, а не вероятность. По структуре бинарного поиска и по тексту Algorithm 1 ожидаемым выражением является `anum - alist[up]`. Поэтому буквальный код может выбирать нижнего по вероятности соседа даже тогда, когда верхний сосед заметно ближе к `epsilon`.

## Решение

Нормализованный ADG следует **семантике публикации**, а не предполагаемой опечатке публичного репозитория:

1. на каждом уровне кандидаты нормализуются и сортируются по убыванию вероятности с детерминированным tie-break по token ID;
2. число бит `b` выбирается так же, как в авторском коде: максимальное значение, при котором `2**b` групп совместимо с текущим `p_max`;
3. при заполнении группы выбирается токен с действительно ближайшей к `epsilon` вероятностью;
4. при точном равенстве расстояний выбирается сосед с меньшей вероятностью, что соответствует предполагаемой логике исходного `near()` после исправления опечатки;
5. индекс группы кодируется/декодируется в little-endian порядке битов, как в авторских `bits2int` / `int2bits`;
6. рекурсия продолжается только внутри выбранной группы, пока нормализованный `p_max <= 0.5`;
7. в терминальной группе токен выбирается пропорционально `P_reference` внутри этой группы.

## Случайность и параметры

В normalized Stage 4 у ADG нет собственных настраиваемых гиперпараметров. `temperature`, общий `top-k` и `top-p` принадлежат построению `P_reference`.

Для терминального стохастического выбора токена используется изолированный `MethodRandomSource`, задаваемый через `method.random_seed`. Это воспроизводимая техническая случайность, но не общий секретный ключ Алисы и Боба: декодеру ADG RNG не нужен. Поэтому `method.key` для ADG запрещён.

## Q_stego

Для каждого шага benchmark независимо от выбранного секретного пути строит полный `Q_stego`:

- перебирается всё дерево рекурсивных групп;
- каждая группа на уровне выбирается с вероятностью `1/u`, поскольку секретные биты считаются равномерными;
- внутри терминальной группы вероятность токена пропорциональна исходной вероятности LM в этой группе.

Полученный явный массив передаётся в общий слой dual-KL/TVD. Сертификат `Q=P` не используется.

## Цель проверки соответствия авторской реализации

Поскольку публичный код содержит неоднозначность `near()`, conformance будет разделён:

- отдельно проверяется всё совпадающее ядро: выбор `b`, формирование групп, little-endian отображение битов, рекурсия и терминальная нормализация;
- отдельно характеризуются случаи, где буквальный `near()` репозитория расходится с nearest-probability правилом статьи;
- это расхождение не скрывается и не объявляется ошибкой нашего адаптера.

## Характерный результат публикации

В Table 1 статьи ADG одновременно показывает высокую embedding rate и малый, но ненулевой `KLD1 = D_KL(p_LM || q)`:

- Movie: ER 5.147, KLD1 0.033;
- News: ER 5.650, KLD1 0.027;
- Tweet: ER 5.411, KLD1 0.048.

Нормализованный benchmark не воспроизводит эти числа один-в-один, потому что использует другую LM, токенизатор, промпты и единый `P_reference`. Характерный публикационный результат для Stage 4 формулируется как **высокая ёмкость при малом, но в общем случае ненулевом распределительном искажении**, измеренном независимым explicit-`Q` и `D_KL(P_reference || Q_stego)`.

## Следствия

1. Публичный GitHub-код не считается безусловным эталоном там, где он противоречит Algorithm 1.
2. Нормализованная семантика заранее зафиксирована до реального Llama-запуска.
3. В отчёте ADG нужно раздельно показать: (a) соответствие авторскому ядру и расхождение `near()`, (b) воспроизведение характерного результата Table 1.
4. Стоимость построения полного `Q_stego` относится к metric instrumentation и не входит в скорость ADG как метода.
