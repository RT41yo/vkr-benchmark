# ADR-0016: Проверка завершения этапа 3 и результатов воспроизводимости

- **Статус:** принято
- **Дата:** 2026-09-14

## Контекст

На этапе 3 проверялась воспроизводимость базовых методов Bins, Huffman и Arithmetic Coding. Для этого были выполнены эксперименты в режиме, максимально близком к авторской реализации, воспроизведена Figure 3 и проведено сравнение авторских и нормализованных версий методов.

При этом нельзя считать этап завершенным только потому, что код успешно запускается или график визуально похож на опубликованный. Нужно было зафиксировать понятные условия, при которых результаты этапа считаются достаточными.

## Решение

Этап 3 считается завершенным, если одновременно выполнены следующие условия:

- проведен полный набор запланированных экспериментов по Figure 3;
- все ошибки и неудачные завершения сохранены и не скрыты;
- основные тенденции Figure 3 воспроизведены;
- результат честно зафиксирован как частичное воспроизведение, а не как точная историческая копия;
- расхождение по значению `4e-8 nats` для Arithmetic Coding при `precision=26` сохранено как реальное наблюдение, а не подогнано под статью;
- сравнение author-compatible и normalized версий показывает, что основная логика Bins, Huffman и Arithmetic Coding сохраняется;
- бесконечные значения `D_KL(P_reference || Q_stego)` сохраняются как корректный диагностический результат и не сглаживаются искусственно;
- итоговый отчет и файлы сравнения сформированы;
- все тесты проекта проходят успешно.

Для автоматической проверки этих условий используется:

`scripts/check_stage3_readiness.py`

## Научный вывод

По итогам этапа 3 можно утверждать, что нормализованные версии Bins, Huffman и Arithmetic Coding сохраняют основные принципы исходных методов.

Характерные зависимости Figure 3 удалось воспроизвести, однако отдельные численные результаты и точная историческая организация эксперимента не были воспроизведены полностью. Поэтому результат этапа корректно обозначается как **частичное воспроизведение**.

## Последствия

Этап 3 можно считать завершенным и переходить к подключению современных стегометодов на этапе 4.

Спецификация benchmark v0.1 при этом не изменяется задним числом. Наблюдения этапа 3, в том числе использование двух направлений KL-дивергенции, сохраняются как материал для будущей версии спецификации.
