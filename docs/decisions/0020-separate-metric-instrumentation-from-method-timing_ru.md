# ADR-0020: Отделение расчета метрик от времени работы стегометода

- **Статус:** Accepted
- **Дата:** 2026-10-03
- **Контекст:** Этап 4, явный расчет `Q_stego` для Discop

## Контекст

ADR-0013 определяет, что показатели вычислительной эффективности должны отражать работу языковой модели, построение `P_reference` и собственно стеганографический алгоритм, но не последующий расчет диагностических метрик.

После перехода Discop на независимое явное построение полного `Q_stego` этот расчет первоначально выполнялся внутри `encoder.step()`. Из-за этого его стоимость ошибочно попадала в `stego_algorithm_ms`, хотя полный `Q_stego` не нужен Discop для выбора токена и используется только для KL-дивергенции и TVD.

Та же граница должна быть однозначной для всех методов, а не только для Discop.

## Решение

Расчет распределительных метрик отделяется от операции выбора токена.

Интерфейс `EncoderSession` получает отдельный метод `distribution_info(context, decision)`. Встроенные методы используют следующую схему:

1. `encoder.step()` выполняет только действия, необходимые для встраивания секрета и выбора следующего токена;
2. `encoder.distribution_info()` строит `Q_stego` и другие данные, необходимые только для метрик;
3. общий runner измеряет эти участки раздельно;
4. время `distribution_info()`, расчета энтропии, KL/TVD и raw-LM NLL учитывается как `metric_instrumentation_ms`;
5. `metric_instrumentation_ms` не входит в `encode_total_ms`, `decode_total_ms`, `stego_algorithm_total_ms`, `ms/token` и пропускную способность полезной нагрузки.

Для Discop независимый явный расчет полного `Q_stego` сохраняется на каждом шаге, но его стоимость относится к измерительному контуру бенчмарка, а не к скорости самого метода.

Для Bins, Huffman и Arithmetic Coding построение полного массива `Q_stego` также вынесено из измеряемого времени алгоритма. Действия, без которых сам метод не может выбрать или декодировать токен, остаются в `stego_algorithm_ms`.

## Следствия

- показатели скорости сравнивают именно алгоритмы, а не стоимость вычисления исследовательских метрик;
- независимый явный расчет `Q_stego` для Discop можно сохранить без искусственного ухудшения его показателей скорости;
- стоимость измерительного контура остается наблюдаемой отдельно через `metric_instrumentation_total_ms`;
- фактическое wall-clock время полного запуска может быть выше `encode_total_ms + decode_total_ms`, поскольку диагностические вычисления сознательно исключены из показателей производительности.
