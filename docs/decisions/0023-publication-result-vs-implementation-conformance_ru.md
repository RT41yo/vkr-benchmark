# ADR-0023 — Разделение воспроизведения результата публикации и соответствия авторской реализации

**Статус:** принято  
**Дата:** 2026-10-10

## Контекст

В Этапе 3 для Bins, Huffman и Arithmetic Coding был доступен единый наглядный внешний ориентир — Figure 3 из Ziegler, Deng, Rush (2019). Поэтому проверка воспроизводимости могла быть оформлена как свип в режиме, максимально близком к авторскому с последующим сопоставлением формы кривых и сравнительного порядка методов.

Для современных методов Этапа 4 публикации формулируют ключевые результаты в другой форме. Для Discop и RRC определяющими являются свойства сохранения распределения, эффективность использования энтропии и корректность полного цикла. Кроме того, эти методы чувствительны к деталям реализации: генератору общей случайности, порядку вычислений, точности, условию завершения и точному воспроизведению последовательности вероятностей у отправителя и получателя.

Поэтому одна проверка «похож ли график на рисунок статьи» недостаточна и не всегда является наиболее содержательным способом проверки.

## Решение

Для каждого современного метода воспроизводимость фиксируется двумя независимыми слоями.

### 1. Соответствие авторской реализации

Цель — ответить на вопрос: **реализует ли наш нормализованный адаптер тот же алгоритм, что и зафиксированная авторская реализация?**

По возможности используется неизмененный checkout зафиксированного коммита авторского репозитория. На одинаковых входах сравниваются алгоритмически значимые результаты: выбранные token IDs, восстановленный секрет, внутренние состояния/границы, число использованных битов, поведение завершения и другие доступные инварианты.

Этот слой не является заменой публикации. Он проверяет корректность переноса программной семантики.

### 2. Воспроизведение характерного результата публикации

Цель — ответить на вопрос: **проявляет ли метод в нашей экспериментальной среде то принципиальное поведение, которое является основным результатом публикации?**

Форма проверки выбирается по содержанию статьи:

- если публикация дает содержательный график/свип и его можно разумно воспроизвести, используется графическое/трендовое сопоставление;
- если ключевое утверждение является свойством распределения, емкости, эффективности или надежности, воспроизводится непосредственно это свойство с помощью метрик бенчмарка;
- точное численное совпадение не заявляется, если модель, корпус, промпты, токенизатор или полный исходный экспериментальный сценарий запуска отличаются или не опубликованы.

## Применение к текущим методам

| Метод | Проверка авторской реализации | Характерный результат публикации |
|---|---|---|
| Bins / Huffman / Arithmetic Coding | проверки режима, максимально близкого к авторскому, на Этапе 3 | тренды Figure 3: компромисс емкости и KL, сравнительный порядок методов |
| Discop | сравнение нормализованного ядра с зафиксированной Cython-реализацией | сохранение распределения и высокая эффективность использования энтропии |
| RRC | прямое сравнение с зафиксированным `rrc_core.py` | практически нулевое распределительное искажение, почти полное использование энтропии, точное извлечение по исходным token IDs |
| ADG | определяется при интеграции | выбирается по публикации до фиксации нормализованной семантики |
| DAIRstega | определяется при интеграции | выбирается по публикации до фиксации нормализованной семантики |

## Интерпретация Discop

Для Discop проверка соответствия авторской реализации подтверждает перенос алгоритма, а проверка результата публикации подтверждается отдельно:

- независимый полный `Q_stego` совпадает с `P_reference` до численной точности;
- оба направления KL и TVD практически нулевые;
- характерный свип по `top-p` показывает высокую эффективность использования энтропии и точное восстановление секрета.

Авторское поле KLD не используется как экспериментальное доказательство, поскольку в исходной реализации оно не рассчитывается независимо.

## Интерпретация RRC

Для RRC прямая проверка соответствия авторской реализации подтверждает совпадение с актуальным `rrc_core.py`, а проверка результата публикации подтверждается отдельно:

- независимый `Q_stego` дает конечные KL порядка численной погрешности и TVD порядка `10^-12` на полнословарной Llama;
- характерный запуск с фиксированной полезной нагрузкой дал 99.277% использования энтропии;
- прямое восстановление по token IDs в серии составило 100/100.

Восстановление через обычный текстовый канал фиксируется отдельно как характеристика слоя транспорта и токенизации и не подменяет алгоритмическую проверку.

## Следствия

1. Репозиторий автора не считается заменой статье; он является эталоном программной семантики.
2. «Воспроизведение публикации» не обязано означать перерисовывание конкретной фигуры. Оно означает воспроизведение заранее выбранного характерного научного результата, подходящего для данного метода.
3. Для каждого следующего метода до интеграции необходимо явно зафиксировать: (a) цель проверки соответствия авторской реализации и (b) цель воспроизведения характерного результата публикации.
4. В отчетах Этапа 4 эти два уровня должны быть описаны раздельно, чтобы было понятно, какое доказательство отвечает на какой вопрос.
